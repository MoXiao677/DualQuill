# 阶段二：整书状态、正文范围锁与保存性能

本切片相对冻结的阶段一作者稳定性工作区增量实现。阶段一文档、数据、日志与三件套保持原样；本文件不改写阶段一测量结论。最终数字、源码 SHA 和所有成功/失败运行见外层 `verification.json`、`HANDOFF.md`。

## 作者入口

- 小说项目页新增整书管理。归档、移入回收站、恢复先请求只读影响预览，再要求输入完整书名、勾选明确确认，并绑定当前整书 revision 和新的操作 UUID。预览/确认失败不落盘。
- 书架可筛选创作中、已归档、回收站、全部。归档和软删除保留正文、稳定 ID、全部实体版本、全部整书快照及正文锁，没有物理删除。回收站恢复回到移入时状态；从归档恢复才回到创作中。
- 非活动整书正文只读，中央持久化入口拒绝普通变更及新的模型运行事件。已经在外部执行的请求不能被归档动作撤回；本功能不声称远端取消。恢复不授予模型外发或解锁许可。
- 章节工具栏“正文选区锁 / 解锁”跳到本章保护面板。先保存正文，再在正文框选择完整字符并明确锁定。面板展示实际被保护原文、范围及绑定版本；每次解锁重新确认。

## 正文锁契约

锁是正文选区保护，不是章节 `confirmed` 状态，也不是大纲字段锁。每章最多 128 个互不重叠的活动范围。坐标为 Python/Unicode code point 的 `[start,end)`，不是 UTF-16 单元、UTF-8 字节或用户感知字素；组合字符保持原样，不做 NFC/NFD 或换行规范化。浏览器把 textarea 的 UTF-16 坐标转换为 code point，拒绝截断代理对。

锁绑定整章原文 SHA-256、所选原文 SHA-256 和当前实体版本。锁外保存可以平移范围并追加 rebase 事件，不能覆盖先前事件。锁内替换/删除/插入、移除带锁章节、过期版本或来源摘要均被拒绝。精确公共前后缀优先；复杂中间改动出现重复受保护文本或无法可靠对齐时保守拒绝，作者需要保留输入并重新核对/明确解锁，不能自动猜测另一处相同文字。

手工保存、历史恢复、整章候选采纳、场景/选区扩写、局部查重修改最终均通过 `SQLiteRepository.save/atomic` 的同一守卫。正文、追加版本、锁 rebase、AI 采纳收据处于同一事务，任一守卫失败一起回滚。解锁事件独立于内容修改，不能在同一 revision 中夹带改文；旧操作号不能当作以后写入的许可。

## 历史、备份和复制

本分支暂用 workspace/backup **V48**，新增 append-only `author_scope_events`；没有改变 SQLite `user_version`。V1–V35 只读打开不升级，第一次明确的新控制操作才升级到 V48。事件绑定项目、操作、章节、实体版本与锁 ID。

完整备份、独立恢复、项目复制均验证并保留事件历史和活动锁。复制重映射项目/章节/实体版本/事件/操作/锁 ID，原文字节及摘要不改变；原库不改写。历史中一次解锁记录不是持续许可，复制和恢复也不复制系统凭据或自动开启模型。真实 V48 备份/恢复/复制与恢复后继续写入/拒绝锁内改文由定向磁盘测试覆盖。

最终并行集成需要统一确认 V48 编号与其他分支是否冲突；本切片未合入主工程、未打包发布。

## 保存优化与不变量

- 手工正文保存从同一写事务读取经过验证的最新状态，仅把目标章节及其版本链物化给既有 `chapters.save`，提交前仍完整验证新整书文档、全部领域集合、历史前缀、实体版本和引用。
- 去掉同一次持久化内的重复文档验证/复制；基础标量仍逐值严格校验，布尔值不能作为整数。旧 V1 缺省字段的无语义变化保存仍保持零写入。
- 每次读取仍遍历数据库中**每一个**整书历史快照，核对确切 UTF-8 payload 的 SHA-256。没有只看 mtime/大小、没有仅核对最新快照、没有删历史。
- SQLite BLOB 逐条读取、最多三个在途快照及两个本地 SHA 工作线程，避免一次载入全部快照。只有完全相同的哈希前缀才复用领域验证结果。来源目录仅含只读标量签名，历史文档和任务状态仍隔离复制；成功提交后才建立新缓存。事务失败、外部同大小且恢复 mtime 的篡改、其他实例写入、返回对象修改均有真实磁盘回归。
- 特性声明扫描只遍历工作区集合；已按严格模型验证的小说文档没有任务协议字段，正文文本不作为结构化声明解析。V28/V29/V30/V33/V34/V35 各自真实持久化和恢复复制由定向测试复核。

固定规模夹具继续使用原来的 500 章、每章 2000 个 Unicode 字符、每章初始五版（共 2502 个实体版本），轮流保存首/中/末章共 30 次，并保留全部早期版本哈希和连续 revision。它保持原 V27、无活动锁的性能口径；不能把这一计时称为百万字带锁压力验收。P95 为 30 项排序后的第 29 项，包含首次冷缓存保存，不剔除异常高值。峰值为该 Python 进程的 Windows peak working set。

`fixed-scale-01/02` 包含导入、备份、恢复及恢复后续写的完整规模流程；后续 `benchmark_only` 报告明确只重测保存/重开/读取，不能将其记作再次执行了完整规模备份。最终 V48 锁的备份复制另有当前源码的磁盘测试。

没有可复现的 v0.2 同机基线，不编造对比。不把离线夹具/loopback 协议供应商称为真实模型验证；没有全量套件、打包、安装器、干净 VM、真实系统输入法或真实供应商计费验收。所有测试、浏览器临时 profile、缓存与日志位于本阶段 G: 根目录，正式数据、8765、作者 profile/凭据和其他工程副本不参与。
