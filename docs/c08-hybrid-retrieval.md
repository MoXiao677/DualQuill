# C08 本地字面混合检索与增量窗口索引（2026-10-21）

这是隔离副本的可整合实现，尚未代表主仓验收或发布。保留原 `literal` 检索默认行为；新增明确选择的 `hybrid` 模式。两种模式都不读取草稿、凭据或外部网站，不调用模型。混合仅指多路**字面**召回与重排，不能称为语义检索。

## 作者操作

1. 本地资料页创建或更新 TXT/Markdown 后，点击“显式增量更新本资料索引”。当前资料未变的固定窗口复用 ID/哈希；修改窗口重算，最后统一事务发布。资料不会在保存、检索或重开时静默重建。
2. 更新过程中可以取消。只有事务回滚后才显示“已取消”；取消与提交竞争时，已提交结果仍显示成功。服务进程关闭会请求取消，重新启动不续跑、不重新发起任务。页面离开只停止轮询，已经明确启动的本进程任务可能完成，回来以实际索引状态为准。
3. “查看可追溯标签建议”只读返回 Markdown 标题及重复词项，附资料版本、精确范围和哈希。最多分析原文前 200,000 个字符、最多十条建议，响应明确报告截断。作者自行填入标签并保存新版本；没有自动采纳或模型标签生成。
4. 从记忆页打开本地检索，明确选择“字面混合：Unicode / BM25 / 短语融合”。本地资料和全局 Skills 仍需逐项选择；不会按标签偷偷扩大范围。
5. 每条结果显示覆盖词项、短语匹配、融合分数及完整窗口引文。勾选后预览的是此窗口，再次核对原资料；没有命中就返回空列表。

后台索引完成不会自动重绘已有未保存资料表单。若表单已修改，会保留输入并提示重新核对保存编号，避免用旧编号覆盖数据。

## 检索算法与明确边界

- NFKC/大小写折叠保持原文 Unicode 码点偏移映射，处理组合字符、全角字符、ß 展开与 Hangul 组合；原文从不归一化写回。
- 中文使用重叠双字词项，其他文字使用 Unicode 单词；短语匹配与 BM25 两路按 reciprocal rank fusion 合并，再按查询词项覆盖率重排。并列顺序确定，不使用随机数。
- 搜索单位为不超过 800 个原文字符的窗口，相邻重叠 120 个字符；查询上限仍为 100 字符。匹配不到的同义词不会被推断；中文双字不是分词模型。
- 查询词项投影只保留每个候选窗口的计数和证据，归一化偏移映射逐窗口释放。检索仍按请求扫描当前合格资料，**没有持久倒排表或持久记忆向量索引**。
- `RankingBackend` 是内部类型契约，`LexicalBackend` 为可运行实现。没有可由 HTTP 参数启用的外部 backend；远程嵌入、向量模型和真实语义质量均未实现。能力返回 `semantic=false`、`embeddings=false`、`remote_embeddings=false`、`network_requests=false`，未知远程参数被拒绝。
- 将来接入远程嵌入必须另行实现逐请求明确预算/外发确认、真实传输、引文复核及质量验收；本实现没有预留静默联网的开关。

## 时效和上下文守卫

- 混合模式排除未确认、归档、来源已过期或有未解冲突的记忆，以及归档/回收章节；默认按有效故事位置排除后续章。显式全书搜索可以展示后续章，选入上下文仍重新排除。
- 资料必须属于当前书，启用且当前版本完整索引通过精确窗口和 SHA-256 校验；跨书、缺失、过期、归档直接拒绝。版本历史和操作历史继续 append-only。
- 新命中的 `selection.excerpt={start,end,sha256}` 最长 800 字符，服务器从真实来源重建并验证范围，拒绝缓存正文、篡改哈希、越界及未知字段。范围是 **Python/Unicode 码点的半开区间**，不是 UTF-8 字节或 JavaScript UTF-16 code units。
- 资料范围以版本原文为基准；记忆和章节范围以检索表示 `标题 + LF + 正文 + LF` 为基准；规划/人物使用既有 JSON 检索表示，Skills 使用文件原文加 LF。引文 SHA-256 对该精确原文子串的 UTF-8 编码计算。
- `previous` 上下文额外排除新混合检索中当前章的正文/记忆，即使未启用已保存汇总。整条来源的预算规则沿用既有上下文机制；发生裁剪时，报告实际 `included_range` 和 SHA-256，不伪称完整引文。
- 新精确检索上下文在发送和采纳时都重读来源、版本、归档/索引、章位和冲突状态；不依赖是否启用汇总。有实际依赖的全局 Skills 在发送前也重读核对。索引/任务自身的 lifecycle revision 不会把仍有效引文误判过期。
- 冻结的新检索任务绑定 `retrieval_owner`。服务重开和恢复不继承执行许可；复制时重新映射该身份，连同进程内复制也不能沿用旧许可。写作仍走既有逐请求预算确认、人工差异复核及正式采纳。
- 工作流组合可读取旧冻结上下文，但新准备会丢弃传来的检索 owner，按本进程重新绑定；清空检索来源的组合不会误继承旧许可。旧历史反序列化仍逐字保留原 owner。

## 增量索引与 HTTP

固定窗口索引仍使用 V25 的 `material_chunks`；没有新表或自动数据搬迁。构建比较同范围旧版本原文，完全相同才复用窗口 ID/哈希并重新绑定当前版本。字符插入导致后续位移会重算这些窗口；不宣称编辑距离算法或磁盘快照持久化是次线性。

- 原 `POST .../materials/{id}/rebuild` 继续可用，返回 `index_update`：复用/重算/移除数和重算范围。原 `rebuild-all` 仍跳过归档资料。
- `POST /api/projects/{id}/materials/{material_id}/index-jobs`，请求仍为 `operation_id` 和 `expected_revision`；返回 202 和本进程任务身份。
- `GET /api/projects/{id}/materials/index-jobs/{job_id}` 返回运行/完成/取消/冲突状态。
- `POST .../materials/index-jobs/{job_id}/cancel` 只接受 `{}`。任务按书隔离，仅一个索引 worker 同时运行，内存最多保留 100 个任务，无正文缓存。
- 相同 UUID 同请求在本进程重放同任务。进程重开后，已提交操作从 append-only 操作记录识别为完成、零重写；未提交/已取消任务不自动重试，新操作需作者再次明确发起。
- `POST .../materials/{material_id}/suggest-tags` 只接受 `{}`，零状态写入，返回当前版本证据建议。
- `POST .../search` 新增 `mode=literal|hybrid`。所有 POST 继续会话令牌/来源检查，未知字段拒绝；不存在/跨书任务为 404，revision 冲突为 409，非法参数为 422。

## 本地建议版本 V44

只有正式准备包含 `excerpt` 或资料来源的新任务时，工作区升级到本副本建议的 V44；查找、标签建议、索引更新本身不触发 V44。新增 `SearchExcerpt`、可选 `SearchSelection.excerpt`、可选 `ContextOptions.retrieval_owner` 与 `material` 依赖/引用类型。旧字段缺省时编码省略，不回填旧 V1–V35 冻结输入。

完整备份、恢复、复制及能力列表支持 36。复制映射资料版本引用和检索执行身份，保留原文、范围、哈希和冻结上下文；原任务不获得新许可。对于带实体 ID 的 JSON 资料，复制可能改变其当前 JSON 表示；旧快照继续保留，须重新检索/准备才可执行。

此编号必须由主整合者与其他并行模块统一分配，不能把本副本 V44 直接当发布号。共用文件及完整变更清单见任务目录的 HANDOFF.md / changes.diff。

## 实际验证与重现

- 新增业务/真实随机 loopback HTTP/虚构模型 wire 测试覆盖 Unicode、无命中、时效、精确引文、预算裁剪、增量范围、事务取消、幂等、重开、V44 恢复复制与不继承许可。
- 额外逐一验证 V1–V35 共 35 种版本基线（含已保存章节、较新集合为空），只读、混合空检索、预览和资料列表均保持数据库字节与版本不变；非空旧冻结历史另由既有 V1/V15/V26/V32/V35 回归覆盖。
- `test_s4a_tasks test_s4a_protocol test_rollup_context test_backups test_backup_validation test_migrations test_migration_preservation test_candidate_review_http` 定向回归 111 项通过，日志 `../evidence/regression-05.log`。这不是完整全量。
- Node 用真实渲染函数与轻量 DOM 测试控制逻辑，不等同于 Electron/CDP 或人工桌面验收。桌面验证、全量及打包留给主整合。
- 可复现实验：`python scripts/benchmark_c08_retrieval.py --output-dir <新的G盘证据目录> --material-chars 50000 --materials 4 --repeats 3`。只创建新的虚构库，拒绝覆盖目录，网络连接被拦截。
- 本次 `perf-01/report.json`：四份合计 200,000 字符，四类查询各三次，查询中位约 307.7–322.1 ms。尾部单字符更新复用 73 个窗口、只重算 1 个窗口，约 355.9 ms（仍包含现有完整持久化校验）。语料 SHA-256 `03aea666de04241a67cbfe3fe7c537c09c6b10b1c1ca176b1c629bc503d1a700`。
- `perf-02/report.json` 为带命令和源码 SHA-256 的复现：相同语料中位约 307.1–357.2 ms、增量约 394.1 ms，同样复用 73 / 重算 1；性能波动保留原值。
- 四个固定字面相关性 top-1/空命中样本通过，不代表真实模型语义质量、百万字桌面或跨机性能。所有真实 provider/付费调用为 0；虚构 loopback 请求单独计入测试，不称为真实供应商验收。
- 原失败和修后日志分别保留；精确命令、退出码、测试数与未测项以 `verification.json` 为准。
