# C09 受控工具与实际用量（2026-10-21）

本增量沿用 V20 会话、V24 显式运行和自然大纲对话。在作者编辑、保存和冻结的计划上增加两种本地确定性只读工具、严格工具提案校验、仅本次请求有效的只读连续推进，以及实际供应商 usage 联动。模型生成的文字/JSON始终是不可信资料，没有脚本、系统命令、任意URL、动态插件、自动付费或自动正式采纳入口。

## 可用流程

1. 在“创作对话 → 操作记录与手动编排”选择工具。`chapter.inspect` 读取已保存章节的字数、SHA-256及前1200码点预览，并明确预览是否截断；`context.preview` 复用既有只读上下文预览，范围为前文、预算6000字符，保留来源/排除/警告报告，不自动引入检索结果或汇总。
2. 也可粘贴工具计划JSON，点击“校验并加入可编辑草案”。只接受 `steps`，每步只接受 `tool` 与注册 `arguments`；预览零持久写入、零任务、零外发。未知工具、未知字段、权限、命令/URL参数、跨书/归档章节、非法场景/选区均明确拒绝。指令中的命令只是文本。
3. 最新自然大纲对话候选可通过显式按钮生成“读章节 → 看上下文 → 准备细纲”的确定性草案。选择现有目标章、编辑并保存后，追加消息保存精确 task/candidate 引用；关联候选可打开原始候选历史。建议只组织操作和关联来源，不自动把全书候选作为章节生成上下文，更不自动写入正式大纲。正式大纲仍走原来的提案/影响预览/人工确认。
4. 保存计划支持 `expected_plan_revision`，过期编辑拒绝。已有运行/派发引用的步骤保留为历史锚点，可以改内容/顺序而使旧运行失效，不允许删除这些锚点。新操作可追加新步骤；会话与消息不删除。
5. 开始运行只冻结计划。普通“推进一步”仅执行一个确定性只读工具，或准备一个既有待确认模型任务。勾选本次允许的只读工具，再点击连续推进，只在该次HTTP事务内按顺序执行允许的只读步骤，最多100步；遇到模型准备、未许可工具、失败或守卫停止。不会启动后台轮询/调度。
6. 每个模型请求仍在原任务页核对确切冻结请求SHA、模型、目的地、预算并单次确认。候选完成后仍须独立复核与正式采纳。连续只读许可不能传入模型准备/发送/采纳权限，也不替代这些确认。

示例（将 `<本书章节UUID>` 替换为目标章）：

```json
{"steps":[{"tool":"chapter.inspect","arguments":{"chapter_id":"<本书章节UUID>","instruction":"读取已保存状态"}},{"tool":"context.preview","arguments":{"chapter_id":"<本书章节UUID>","instruction":"核对来源与排除原因"}}]}
```

## 状态、幂等与恢复

- 暂停后拒绝推进，恢复不自动执行。计划变化、会话/目标章归档、输入/模型配置变化、任务失败/取消/中断、非法候选等均有可读阻止原因，不自动跳过。跳过和取消都保留既有结果、候选及追加历史。
- 只读结果追加到原 `console_messages`，关联计划步骤；运行详情展示精确保存的结果及消息ID。中途确定性工具失败时先前成功结果仍保存，当前步骤标记失败，须明确跳过或取消。
- 运行操作使用既有 `operation_id` 与乐观修订号。同请求重试幂等；同编号改只读许可拒绝。同协调器的运行/计划/暂停取消操作串行；准备任务使用稳定的“运行+步骤”身份，准备已成功但派发记录失败后重试复用原任务，不能偷偷生成第二个待确认请求。
- 已采纳步骤之后推进下一步的游标守卫已修正；最后一个模型步骤采纳后仍保留可点击推进，用显式动作完成运行，GET不暗写状态。
- “取消编排”停止后续步骤；已经发送的模型请求仍在原任务页取消，界面与历史消息明确区分这两层状态。
- 重开、备份恢复、复制只展示保存状态，绝不续行或重发。许可只在当前advance请求内有效，UI复选框每次重绘都未勾选；持久消息记录许可的历史事实，不赋予未来执行权限。

## 用量来源

- 会话、运行步骤、自然大纲对话共用只读usage投影；从持久供应商 `responses/model_results/late_results` 中的 `response.usage` 读取实际prompt/completion/total token，以发送事件统计尝试次数，并提供response/record/attempt来源。
- 不用候选字数、输出token上限、手工价格或风险预算冒充实际用量/账单。缺失计数保持 `null`，显示未知；部分报告的小计与完整总量分开。不可读任务的发送次数和费用也保持未知，不回填0。
- 当前响应契约没有已结算货币费用，因此实际费用保持未知；尚未发送与发送后费用未知明确区分。无任何真实账单或语义质量验证承诺。
- 候选关联消息中的同一task引用不会重复成为对话轮次，也不会重复计费或重复加入后续模型历史。

## API增量

- `GET /api/projects/{id}/console/sessions/{session}` 增加 `tools`（严格JSON schema、权限、确认归属）和 `usage`；运行详情步骤增加 `result/usage`，运行增加 `usage`；自然对话增加按唯一task汇总usage。
- `POST .../sessions/{session}/proposal-preview`：`{proposal:{steps:[{tool,arguments}]}}`，零写入。
- `POST .../sessions/{session}/candidate-plan`：`{candidate_id,chapter_id}`，校验候选属于本会话，零写入。
- `POST .../sessions/{session}/plan`：原 `steps`，可加 `expected_plan_revision/candidate_id`；保存候选关联须再次校验会话归属。
- `POST .../runs/{run}/advance`：原 `operation_id/expected_revision`，可加 `allow_readonly:["chapter.inspect","context.preview"]`，仅当前请求有效。任何付费/采纳/未知工具许可拒绝。
- 静态白名单增加 `/console_usage.js`，不开放路径/URL执行。
