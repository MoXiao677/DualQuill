# 0.4.33 人物关系保存与历史读取

人物关系的规范字段为 `target_character_id`、`relation` 和可选的 `description`。资料维护现在先校验本轮所有关系，再保存摘要或人物；无效别名、未知目标和类型错误进入可取消的资料格式重试，反馈包含具体校验原因。直接人物保存也使用相同预校验。既有正文和独立审核凭据不因本项修复而重写。

历史读取改用每本书独立的锁，共享锁只保护缓存和锁表。不同小说不再因另一本文本的历史校验占用同一个存储锁。保留逐条历史摘要核验、领域校验、事务和缓存上限，没有删除历史。

JSON 资源预检可在保守节点上界内一次扫描完整转义字符串；超过上界仍使用精确计数。字节、深度、节点、重复字段、数值和 Unicode 约束保持。

在隔离数据库副本上的单次顺序测量：历史较大的项目首次读取从 60.524 秒降到 44.713 秒，热读取约 1.33 秒；小项目首次读取约 0.067 秒。该测量不等于界面端到端验收，也不代表首次启动卡顿已经彻底解决。完整历史首次领域校验仍是已知性能限制。

回归覆盖关系失败前无业务写入、纠正后单次保存、合法关系与错误目标、跨书历史锁隔离、长篇转义文本扫描。更新旧测试中的 HTTP 长度与 watcher 清理夹具，并验证实际请求信封中的会话隔离和原始作者要求。

使用同一隔离副本和运行记录测量新书聊天视图：首次 0.163 秒，热读取 0.002 秒，响应 33578 字节。这只覆盖后端视图接口，没有验证真实窗口的渲染、设置往返或输入响应；旧窗口仍运行旧版本，重启后才会使用新代码。
