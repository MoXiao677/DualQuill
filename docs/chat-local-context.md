# 聊天创作的本地上下文与请求追踪

## 每轮请求与本地事实

聊天轮次由本地任务管理；模型请求本身按无状态方式发送。每次请求都会重新组装当时保存的小说事实，并保留作者提交的原始需求。规划对话中的最近聊天记录只是补充参考：最多带入最近 6 条，每条最多 1,500 个字符；它不能代替已保存的小说资料，也不能作为已保存或已执行的证明。

同一请求准备流程用于规划、正文创作、审核、审核修订及正文通过审核后的资料维护。各阶段因此都以当前任务修订号对应的本地状态为准；若修订号不符，或小说不再处于有效状态，请求会停止。保存、导入和资料维护仍由本地服务处理。

情节、全书大纲、作者偏好与文风规则，应通过相应的真实保存操作写入本地资料后再供后续请求使用。例如，将情节进展保存为剧情记忆；将全书规划保存为全书大纲；将偏好保存为文风规则。单独出现在聊天对话中的内容，不应被描述为已经保存。

## 本地 Skills

Skills 在本地导入，并按任务选择冻结为该任务快照；选择可以是自动可用项、明确选择的项目，或空选择（禁用）。冻结内容包括所选 Skill 的主文件和允许加载的引用资料。快照用于该任务后续请求，不等同于模型已经遵循这些内容。

公开任务状态只展示 Skill 名称、路径、字符数与哈希等清单元数据，不公开快照正文。任务日志可保留每次请求的完整追踪记录。

## 资料范围与参考资料

上下文按当前小说范围筛选：不把其他小说的资料混入请求；隐藏或删除章节、归档对象及超出目标范围的未来章节正文，不作为当前可用正文事实。附件须符合本轮状态与小说绑定条件。参考资料的常驻上下文是元数据，不是整份资料正文。

实际资料正文通过 `read_material` 分页读取。已保存的分页结果只有在材料仍属于当前小说、未归档、版本仍为当前版本，且分页范围与正文逐字符一致时才会再次纳入请求。失效或不一致的旧分页会被排除并标记；需要时可重新读取。追踪记录对实际纳入的每页保存材料编号、版本编号、字符偏移、结束位置和正文哈希，不记录该追踪字段中的整页正文。未验证的分页内容不会以猜测或回退文本替代。

## 长度、对话与追踪的含义

请求内容执行 360,000 **字符**上限检查。字符数不是 Token 预算，也不是对特定模型可用上下文容量的识别或保证。实际服务商、模型和接口还可能有各自限制。

请求追踪区分准备完成、请求已尝试和收到 HTTP 响应，并记录适用的 HTTP 状态码；日志还会记录本地纳入内容的哈希与覆盖信息。这些字段只能说明本地准备或传输阶段发生了什么，不能证明模型已读取、理解、遵守或交付了任何内容。

## 范围与验证说明

本次独立章节审核修复已修改代码：自动修订不设固定次数，每次有效审核未通过都窄范围修订、保存并再次独立审核，直到通过、作者停止或发生实际异常。空白或相同修订仍视为无效响应；取消、资料修订号及连接守卫继续生效，已保存草稿、正文版本与审核历史保留，最终正文哈希校验不变。审核进度显示章节与轮次，修订进度显示章节与修订次数，最终资料维护单独显示进度；失败或取消后显示中断或停止。错误回执中的已保存章节编号按原顺序去重，完成操作数仍仅取真实完成的复合操作计数。
