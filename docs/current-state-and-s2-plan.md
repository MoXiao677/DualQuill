当前作者服务使用 `G:/AGI/AI-Novel-Writer/data/novels.sqlite3`。只读查询确认三张业务表与三条快照保护触发器，`PRAGMA user_version=1`；当前 `workspace_version=1`、`schema_version=1`。正式库当时有1个项目、8条项目快照、0条 Skills；这些计数不代表已覆盖有 Skills 的完整恢复。

| 对象 | 必须保留的真实范围 |
|---|---|

| 工作区 payload | `workspace_version, revision, document, ideas, worldbuilding, writing_rules`；IDEA键为章节稳定ID |
| `document` | `schema_version, project, book_outline, chapter_outlines, characters, chapters, versions`；各dataclass全字段，包括作者/语言/状态/时间/目标/备注等 |
| 嵌套结构 | 大纲 `volumes/key_events`、人物 `relationships`、细纲 `character_ids/scenes` 等；无完整编辑入口也不能丢失 |

| 历史保护 | `snapshots_no_update/no_delete/no_replace`；恢复后用可信schema建立并验证 |
| 独立设置 | DPAPI混存配置与密钥；仅白名单非敏感配置可导出。UI偏好在浏览器，正文/需求草稿仅内存 |

## 4. 首批方案（待实施）

优先冻结样本和契约，先做备份—恢复—迁移闭环，再测量并决定拆表。S2–S7阶段顺序保持。

建议初版ZIP包以 `manifest.json` 和 SQLite一致性快照 `snapshot.sqlite3` 为核心，可附白名单非敏感设置。先沿用三种版本=1，包独立使用 `backup_format_version`；格式冻结/文件命名/限额是A批交付，当前尚无该格式实现。

manifest包含软件/包/数据库/工作区/小说版本、UTC时间、选择的项目和数据范围、实际表/列/触发器清单、文件大小/SHA-256、每表及每项目实体/版本/整书快照数量、包含/排除项、依赖与设置范围。全部计数和校验从冻结快照读，不能拼接变化中的源数据。SHA-256用于完整性，不宣称提供来源认证。

默认完整小说库备份含全部三表；单项目包仅含选定项目及全部历史，不夹带其他小说。Skills无项目归属，迁移预览明示全局Skills范围，不编造关联、不按名称或内容去重。明确选择排除后列损失并称选择性迁移。

密钥/token/DPAPI凭据文件/可执行扩展不进包。非敏感配置只白名单取站点标识、固定地址、模型ID等，新机重新配置密钥；历史检查不能冒充新机连接成功。浏览器偏好和未保存草稿独立选择，当前内存草稿需配合后续S2-06才能持久恢复。

备份用 SQLite 一致性备份接口；完成并关闭快照后校验、制作包，在同卷临时位置写完校验后发布。失败不产出成功文件、不改源库、不静默覆盖已有备份。并发保存时包内项目/历史必须属于同一个一致数据时点。

恢复先预检到受控暂存目录：拒绝缺清单、未知格式/字段/表、坏内容、重复/大小写冲突ZIP路径、路径逃逸、绝对路径和超限。限制条目数、单文件/总展开大小、流式累计字节，检查磁盘空间/取消清理；限额据合法长篇样本制定，不能只因历史高压缩比拒绝合法包。禁止直接 `extractall` 或执行包内脚本。

SQLite先只读检查schema、`integrity_check`、`foreign_key_check`、所有JSON/领域/历史语义，不先实例化会初始化schema的repository。用可信目标DDL和参数化INSERT重建，不执行包提供的任意SQL/trigger。保持历史保护，不用replace、关触发器或事后改历史。

数据库级预检检查SQL与payload的项目ID/revision/title、每条快照的ID/revision、revision连续至当前、最新快照等于当前payload、相邻快照版本列表不可变前缀、时间格式及历史嵌套引用。引用按相应历史状态判断，不能只对照最新对象。完整包缺持久字段应拒绝；严格解析重复键/非法常量，未知数据不静默丢弃。

空目录完整恢复保留全部ID、revision、时间、顺序、全字段/原文；重开校验后发布并保留源库。已有库默认新项目：按全部历史联合ID集合一次建立映射，再转换所有当前/历史payload和version.snapshot。覆盖项目/实体/版本/前版/当前版ID、IDEA键、卷/细纲/场景/人物关系引用；卷/场景没有独立ID，保留number/order。仅转换明确引用字段，不全局替换正文中的ID字符串。

已有库合并在单连接的一次 `BEGIN IMMEDIATE` 中，锁内复查冲突再一次提交全部项目/历史/Skills。任一失败全部回滚，已有项目不变。Skills同ID全字段相同可明示复用，不同则重映射并报告；不同ID的相同内容仍保留独立记录。复制后项目编辑隔离，全局资料共享边界另行说明。

SQL提交与外部设置不是同一原子操作。首批设置作为已验证附件，数据库成功与设置应用分别报告，不先覆盖现有设置。整库恢复仅发布到新路径，不热替换作者正在使用的数据库；最终目标出现冲突则拒绝发布。发布无覆盖竞争必须实测。

旧小说JSON、工作区JSON和v0.2SQLite分别识别，不能靠扩展名猜格式。旧JSON只导入实际数据，缺IDEA/设定/项目历史/Skills需报告，初始导入快照不冒充原历史。允许缺省值只规范化一次、明确报告并保留原始输入；未来版本拒绝。若升级存储，在新目标库转换、保留旧库回退，不承诺旧程序直接读新格式。
