## 现场与计划

- HEAD、分支、已有修改/未跟踪文件、基线报告路径：
- 当前正式监听者/源码与运行差异（只读元信息）：

- 验收条件；需要用户验收或授权的具体项：
- 实施顺序和选定检查：

## 验证与修复

- RED：命令、退出码、失败原因和日志；已有修复则说明只独立复验：
- 实际修改及其目的：
- GREEN/回归：命令、运行环境、用例数、退出码、日志、未运行项：
- 自动修复尝试 1/2/3：每次的新证据/假设/结果；原失败日志保留：
- 独立审查：模型、只读范围、原始意见、主负责人复核；不可用时如实写明：

## 交付判断

- 已实现 / 已测试 / 已通过验收 / 尚未验证，分别填写：
- 本轮与基线的文件差异、删除/额外新增、敏感提示的核验：
- 更新 TASKS/CHANGELOG/必要架构和状态入口；历史证据不改写：
- 已知限制、正式服务是否加载新代码、下一步：
- 继续当前已授权任务 / 等待验收 / 因具体授权缺口停止某项操作：

模型不得自行用“测试全绿”替作者勾选阶段验收。未验收不能自动推进下一阶段。
