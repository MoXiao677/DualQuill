# 0.4.6：明确启用的已保存汇总上下文

**0.4.6固定包另有两个真实独验RED：显式memory检索可绕过当前章/冲突排除，以及没有rollup依赖时漏掉发送复核。下文是已实现主流程与目标契约，不能称这些边界全部通过；修复进入0.4.7。详见[固定包及RED](final-local-0.4.6.md)。**

## 作者操作

只读上下文预览、模型改写/审核准备及初稿/续写准备新增「启用已保存汇总」复选框，默认关闭。启用后预览实际资料串与每项来源报告，再冻结请求；模型仍须原有逐请求确认，系统不会自动提取/更新记忆、重建汇总或写正文。本功能消费作者已保存的确定性汇总，不是模型语义摘要。

API 沿用 `POST /api/projects/{id}/context-preview` 的 `include_memory_rollups:true`。初稿/续写的 `context_options` 和任务准备的 `context_options` 接受同一选项。必须是明确布尔值；缺省或false保留旧行为。`scope="previous"` 只允许目标章之前，`through_current` 才明确允许目标章，仍排除未来章。未保存草稿不读；声明位置和来源位置取较晚者。

## 选择与预算

只消费当前书已保存、来源未过期、无冲突、相关章节未隐藏的汇总。分卷汇总须属于写作章所在卷，且截至章仍在该卷。按截至位置从近到远稳定排序，同位置依次单章、分卷、全书、ID；全书/本卷各选最新可用一项，单章各选一项。较新的过期项不会挡住较早仍可用项。未来/当前、异卷、隐藏、冲突、过期、旧项覆盖均只报告ID、版本、位置和原因，不回显被排除原文。

同一记忆ID只出现一次。先选汇总中尚未覆盖的来源块，保留原记忆标题、原文和版本，使用既有确定性渲染；重叠汇总只补充未覆盖的来源块。同一记忆的原始记忆及显式检索项若已被汇总选入，报告 `memory_covered_by_rollup` / `search_memory_covered_by_rollup`，不重复计预算。新模式下原始记忆也遵守previous排除当前章、冲突来源排除；关闭选项时不改变旧原始记忆契约。

作用域强制规则先占预算。每个汇总来源块连同标题/分隔符必须整体放得下才选入；不足则逐来源记录 `budget`，不会截半条事实，也不把未放入的记忆记为已覆盖。预算仍是Unicode字符数128–20000，不是精确token数。来源报告 `kind="memory_rollup"`、`entity_id`、`version_id`（不可变history ID），`source.rollup_revision`、完整保存汇总 `source_sha256`、本次选入记忆ID及逐项排除原因。汇总被全部覆盖、为空或预算不足分别报告 `rollup_covered|rollup_empty|rollup_budget`。

## 冻结与兼容

正式冻结资料串保持逐字不可变。依赖使用 `kind="memory_rollup"`，冻结汇总ID、history版本、完整保存快照SHA、截至章及来源记忆引用。首次任务真正选入汇总依赖才升级V32，纯预览不写入。发送前重新校验依赖/新冲突/位置/预算，但绝不改写已确认的请求体；变化拒绝并要求重新准备。采用候选时保持同样保护。初稿/续写还沿用原实际来源语义指纹和配置守卫。

ContextOptions缺省False编码时省略新键，旧FrozenInput解码/编码、旧request_body/request_sha256和SQLite原快照均不改。V31及以前夹带汇总依赖拒绝。完整备份恢复复制支持V1–V32；复制映射汇总、history版本及来源引用，并使用原修订状态重算映射后的依赖SHA。冻结上下文原文字节仍保留，不把旧模型许可带入新书。
