## 键盘与输入

- 使用隔离浏览器 CDP `Input.dispatchKeyEvent` 验证 Ctrl+S、Tab/Shift+Tab、Ctrl+K、方向键/Enter 和 Escape；不向作者桌面发送按键。
- `compositionstart` / `compositionend`、`KeyboardEvent.isComposing`、keyCode 229 为**合成 IME**，分别记录组合期间保存/命令执行抑制及组合结束后的正常行为。它不等于 Windows 真实系统输入法验收。
- 保存正文、未保存正文跨页面恢复、锁内改文拒绝后原输入与原已保存正文保持、深审准备失败后输入保留、非正文表单草稿往返均单列断言。
- 所有模型连接仅为本项 G 盘虚构配置。无真实供应商/密钥读取，无真实付费，无跳过逐请求确认、来源身份、revision、历史 SHA 或人工写入门。

## 运行条件与边界

准备期间的轻量静态事件回放已发现命令搜索 Enter/ArrowDown、正文查找 Enter/Escape 在合成组合状态仍执行的缺口。首轮回放中全局处理器的 CRLF 提取失败独立保留；纠正测试提取器后 20 项中 12 个真实失败、8 个通过。最小修复统一检查本窗口组合状态、`isComposing` 与旧式 keyCode 229，并补齐 Ctrl+K 的 229 保护。它不改变业务写入、来源、历史、许可或事务规则；实际浏览器复现与四尺寸结果仍待父授予窗口。

实际 UI 运行已在父明确授予的独占窗口执行，只在本任务 `temporary` / `evidence` 新建库、profile、TEMP/TMP，使用随机 127.0.0.1 端口且拒绝 8765。baseline 只读复现；其他副本、主仓、正式数据与作者窗口均不参与。

## 实际结果与修复

- `baseline-ui-red-01`：28 格均有截图/几何；131.495 秒，退出 1。关闭的 details 子控件被 `getClientRects` 误计；导航未等 DOM 真正替换导致并发导航及后续超时。这些驱动失败全部保留，不能把它们当成正文规划真实遮挡或产品输入丢失。
- 修正可见性筛选并等待新 DOM/业务空闲后，`baseline-ui-red-02`：37 项中 34 通过、3 个有效 RED，27.646 秒，退出 1。规则页 390px 内容区 327px、scrollWidth 626px；规则审核未保存风险预算跨页重置；合成 IME Enter 实际执行主题命令并关闭命令框。
- 最小修复：规则审核预览/历史 `pre` 精确换行；规则准备连接及数值草稿按书仅存本窗口，不保存费用或执行复选框/来源预览/发送许可；命令和查找组合输入守卫见前节。
- `workspace-ui-green-01`：28 格几何/截图与 9 项键盘/输入检查，合计 37/37，27.167 秒，退出 0；虚构供应商调用 0、真实付费 0，渲染异常及页面外部请求均为空。
- 定向 Node：键盘 24 项 + 原规则审核 UI/草稿状态回归，合计 36/36；详见任务根日志摘要。未以此代替实际 CDP。

三轮浏览器及后端均正常退出 0。实际 CIM 进程归零核查、完整文件/截图/日志 SHA 与本项资源释放时间见任务根 `verification.json` 和 `evidence/process-release.json`。正文锁拒绝后保留失败输入且已保存内容/revision 不变，解锁仍需独立确认；未重测旧库/备份恢复复制，不将它们标为本轮新通过。
