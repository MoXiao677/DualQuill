# C12 多题型、多配置竞技场（隔离交付）

2026-10-21；基于 S6A，不是独立任务引擎。正式整合、全量、桌面与打包由主整合会话统一执行。本模块真实供应商调用为 0；协议/引文/事务测试不证明真实质量、公平排名或账单。

## 实际入口与支持范围

章节写作 → 同题盲评比较 → 选择整章改写、章节细纲或模型审核 → 明确 2–8 个连接/模型/采样配置 → 填写共同要求与评价要求 → 共同冻结。原短试写及文风双配置链保持原有入口与用途，短试写仍为双配置。

改写、审核复用 `TaskCoordinator._preparer`；细纲复用 `ChapterPlanningCoordinator._preparer`、原请求/取消/JSON/场景与人物校验。一次仓储事务冻结所有子请求，任一配置/来源失败全部回滚；所有同题请求的共同消息摘要和冻结来源必须相同。审核按现有模型审核 JSON 严格验证 Unicode 引文，不以传输成功冒充审核正确。空正文/细纲的资格继续由原流程判断。

每配置单次确认确切请求摘要才可发送；不批量自动执行、不自动重试。明确次数与预留输出 token 总上限必须覆盖全部配置，最多 8 次、65536 输出 token；每请求保留原输出 token、超时和风险预算。输入 token 在供应商返回前未知，UTF-8 请求字节只按字节展示；美元风险预算不是供应商费用硬封顶。

## 盲态、评分和人工采用

配置核对页不返回 A–H 映射或子任务身份。全部子任务终态才展示匿名结果；普通工作区、任务/报告列表与细纲列表/详情都隐藏未揭晓子项，细纲执行、修正、复核和采用旁路也拒绝。内部持久、完整导出与备份保留映射；作者主动查看完整导出、已知模型文风或模型在正文自报身份不属于加密对抗保证。

所有配置都必须先追加作者评价：成功结果 1–5 分并绑定实际候选/审核报告与输出 SHA；失败、取消、中断只可 `unscorable` 且 rating=null，不能变成 0 分败者。揭晓引用全部配置此前保存的最新评价；评分、揭晓、选择均可幂等重试，历史不可改写。来源变化展示提示，原结果保留冻结身份；旧配置不能继续发送，需作者新建实验。只读重开不会发送或自动修复历史。

选择胜者只读打开改写候选/细纲 JSON/待核实审核报告；不写正文、正式细纲、记忆或采纳收据。改写仍可明确保存参数预设，后续使用预设清除原未知费用许可并重新确认。细纲/审核须另外走原本的人工复核和正式采用流程。

## 用量与价格来源

逐请求分别展示供应商报告的输入、输出和总 token；缺失字段为未知，不从文本估算、不写 0。耗时为任务开始到结束的墙钟时间，含业务开销。

默认无价格来源，实际费用 `cost=null`。作者可逐配置明确输入每百万输入/输出 token 手工价格、币种和来源说明；非有限数、负价格、缺来源拒绝。该数据随实验冻结，配置准备页可核对。为免手工价格与匿名配置关联，匿名结果不含价格来源；揭晓后才根据真实 usage 展示 `manual_usage_estimate`，注明未核实、不是供应商账单。缺输入/输出 usage 时仍无法估价。系统不虚构默认报价，不把手工估算当实际账单。

## 持久化、复制及整合

新实验为 `arena_version=1` 变体，首次新写使用建议工作区/完整包 V38；没有新 SQL 表或新任务运行时。原 V1–V35 和原 S6A/短试写实验的读路径不补字段、不落盘升级。V38 编号需由主整合统一分配。

复制沿用既有全部历史映射：配置、任务、细纲候选/审核报告、评价/揭晓/选择均重映射；审核结果的派生 SHA 随证据身份重算。原请求正文保留为历史 wire 内容；不把重映射 ID 改写成已发送的请求。复制不复制凭据或进程内请求许可；细纲 owner 与原采用复核许可不继承。准备/重开/恢复本身无外发。

本地验证命令与准确结果、原失败和未测项见交付目录 `verification.json`、`HANDOFF.md`。本次不做真实模型质量评比、真实报价核验、干净 VM、安装器、全量或桌面打包。
