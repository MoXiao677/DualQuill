## 恢复分区故障现在可见且可重试

- 草稿目录无法创建不再阻断已保存项目启动；读取目录失败明确提示，已有正文仍能打开；单文件权限失败单独计入 `unreadable`，不伪称内容损坏。
- 无效保存编号、无时区时间、非法 Unicode、深度异常 JSON 不进入编辑器；有效的其他项目草稿不会误报损坏。
- 写入仍用同目录临时文件、flush/fsync、原子 replace；磁盘满/权限注入失败保留之前的恢复草稿和窗口输入。没有填满磁盘或改真实 ACL。
- 状态栏持续显示恢复草稿异常。清除失败明确提示可能再次出现旧草稿，保留可重试项；不能把正式保存已经成功报成未保存。
- 设置中的“重试恢复草稿读写”重试未完成清除、当前内存草稿写入和当前项目读取。重新读取不覆盖更晚的内存草稿，也不自动提交正式正文。

## 脱敏诊断和选择性清理契约

入口是设置中的“本地诊断与恢复草稿”；仅显式点击后扫描应用自己配置的草稿目录。HTTP：

- `POST /api/settings/local-data/preview`，只接受 `{}`，只读文件，返回报告、五分钟有效的本进程预览令牌、随机条目 ID、大小与通用标签。
- `POST /api/settings/local-data/cleanup`，只接受 `preview_token`、`selected`、`confirmation`（确切 `清理损坏草稿`）。UI 逐项勾选后再次确认。服务端不接受任何客户端文件路径。
- 可复制诊断 JSON 只含格式、模式、数据库/恢复分区大小、有效/损坏/保留数量与固定能力布尔值。不含正文、书名、项目 ID、文件名、绝对路径、提示词、任务原文、凭据或原始错误。诊断不是完整备份，也没有自动外发。
- 仅已知 SHA-256 命名、普通单链接、1 MiB 内的损坏恢复 JSON 可选。有效草稿、未来版本/未知可解析格式、未知文件、超限文件、硬链接/重解析点和目录全部保留；不递归、不接触历史/备份/凭据/暂存 authority。
- 执行前在同一草稿锁下核对每个所选文件的设备/对象/大小/mtime/完整 SHA-256 和目录身份；任一变化时先于首次删除拒绝。预览过期、进程重开、未知 ID、重复/空选择均拒绝。执行阶段遇到 I/O 失败按实际完成数和剩余数返回，不伪造全部成功；必须重新预览重试。
- 删除损坏恢复草稿是明确不可恢复的操作，UI 预览和确认都说明。没有自动“可删建议”、历史瘦身或整目录清理。对同用户恶意进程在系统调用之间主动竞争不提供对抗保证。

## 长篇根因与性能边界

原固定夹具 500 章，每章 2000 字符、五个真实实体版本（总 2500 个章节版本，加项目和分卷版本），在独立库执行真实保存。100 万按现有规模脚本的 Unicode 字符口径，含标点；不是 100 万个纯汉字，也不是 100 万词。

定向 profile 发现一次冷读累计调用 `typing.get_type_hints` 44,160 次，重复解析同一静态数据类注解占主耗时。本批仅缓存最多 32 个不可变类型元数据映射；不缓存作者字段值的验证结果，不取消任何 snapshot 字节 SHA、版本链、时间、实体关联或旧库验证。

同机同夹具修前保存首/中/末约 8.62/8.78/9.03 秒；修后约 2.53/2.48/2.53 秒。修后冷重开 2.84 秒；30 次同实例热读 P95 0.2868 秒；备份 10.12 秒，独立恢复 10.96 秒，完整规模链路 51.26 秒，峰值工作集 339,087,360 字节（约 323.4 MiB）。本机同时有其他隔离任务，不能把该差异解释为跨设备严格性能承诺。

**保存只采样三次，仍高于 PRD 的 P95 <1 秒目标，未做 30 次保存 P95 验收；整体性能指标不宣布达标。** 初始五版是标准化虚构夹具，不是五轮 500 章各自 HTTP 保存；实际后续保存、历史恢复、再保存均走业务事务。百万字桌面渲染、30 次冷启动和 v0.2 同夹具对照本批未重验。
