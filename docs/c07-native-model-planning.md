# C07 阶段二：原生正文驱动模型建议

2026-10-21 隔离工程增量。阶段一只是正文上下文准备、导入和待审提案；不能将其当作原生模型补全。本阶段接通实际模型建议执行链，但所有验证只使用虚构内容及随机 `127.0.0.1` 供应商，未使用真实模型或真实凭据，不代表语义规划质量验收。

## 作者操作

1. 打开大纲页的“正文驱动规划 / 偏离提案 / AI 补全”。明确选择本书启用的已保存正文、选入人物、连接、模型、采样、上下文/输出/时限及累计预算。
2. 来源预览只读，不发送。来源包含唯一已保存章节全文、明确选入人物、适用有效规则、世界观、书纲/章纲、C07 计划及锁/归档状态。其它规则只有一致性摘要，不发送其原文；编辑器未保存草稿不进入来源。
3. 冻结请求仍不发送。展开完整 wire JSON、模型/目的地址/协议/JSON 或 SSE、来源指纹、请求摘要、次数/预留 token/单次风险预算和时限；逐任务勾选确认才可发送。费用未知的风险预算不是实际账单硬封顶。
4. 使用共享 `TaskCoordinator` 执行名额、能力白名单及 `ConfiguredHttpTransport`；Chat / Messages / Gemini 各自沿用真实请求编码与 JSON/SSE 解析。任务最多发送一次，不自动重试。SSE 仅显示转义的进程内临时预览，合法终止前没有候选。
5. 完整合法 JSON 须有 1–20 条 `suggestions`。每条包含待核实理由、Unicode code point 起止、与保存正文逐字相等的非空引文、1–20 项已注册 C07/F1 动作；发生记录必须来自同一章和同一精确引文。禁止模型解锁、执行工具或改写正文。结构与原命令模拟校验不等于语义正确。
6. 作者可以只选择其中一条建议，先“预览本条转提案”，再独立确认“仅保存本条待审提案”。原子保存包装提案和模型关联，正式规划尚未变更。F1 仍先保存原 `planning_proposals`，再经原收据决定。
7. 在下方待审提案查看原影响预览、逐实体变化、偏离计数和后续引用影响；再独立接受或拒绝。正式变更只经原 C07/F1 事务，不写正文。接受一条导致正式基线变化后，其它旧建议需重新生成；不做隐式 rebase 或批量自动接受。

## 冻结、失效与取消

- 准备绑定保存编号、精确来源/规则/人物/规划/锁/生命周期、连接配置、完整原始来源 JSON、wire 请求、预算摘要与本进程 owner。发送须同时确认精确请求摘要、预算摘要及准备后保存编号。
- 发送前、实际工作线程执行前、完整返回时、转提案时和接受前均校验来源。正文、人物、计划、规则、归档或锁变化拒绝旧结果；配置启停、模式或版本变化也拒绝。普通任务事件不错误地使自身来源失效。
- 共享执行名额不会被本模块绕过。累计次数与预留输出 token 从已开始的本书正文规划任务计数；取消/超时不返还。连接原有速率限制仍生效。
- 取消与超时是终态；迟到响应可保留为不可执行历史，不产生候选或提案。非法/截断/工具式输出只能失败。关闭或重开后，旧 pending/running 任务不能续发。取消请求如果到达时任务已结束，界面如实显示未新增取消决定。
- 转提案和影响预览许可都是当前进程内随机令牌，并绑定当前保存编号；不会写进可继承的授权状态。恢复后的合法候选必须重新显式预览；旧发送/转提案/接受令牌不继承。
