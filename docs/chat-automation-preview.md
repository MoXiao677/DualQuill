# 聊天自动创作试用版 0.4.17

本版本新增本地附件上传、拖放与显式本地路径导入：源文件只读解析并保存在本机附件库，聊天发送时才交给当前选定模型分类。支持 TXT、MD、DOCX、文本 PDF；原件可下载、归档和恢复，归档不会撤销已保存的正文或设定。完整章节使用来源分节逐字导入，不由模型重写；本地路径导入最多处理 30 个文档。分类报告使用中文类别名，并在任务失败时仍汇报已实际保存的项目与来源。

本轮用户明确授权修改源码，以“添加一次 API，随后通过聊天维护小说”为目标；覆盖历史文档中逐请求冻结、逐条人工采纳作为唯一入口的限制。保留原来的手动业务、正式正文版本和历史快照，不直接修改 SQLite 内容。用户现已授权将本版源码提交并推送至 GitHub。

## 使用

1. API 设置选择已有连接，或填写 API 地址、密钥与模型编号，保存。
2. 回到创作对话，输入建书、人物、世界观、规划、写章节或修改要求。
3. 操作进度显示在聊天底部。章节正文在章节列表查看，资料在可选查看区查看。
4. 连续写多章按章请求、按章保存，每章后请求模型同步剧情摘要、人物状态、伏笔和世界观。中断不会自动重复付费请求。
5. 可通过聊天删除或恢复章节、人物、记忆、世界观、规则及大纲。书架提供本地书籍删除/恢复按钮；删除整本书需要确认，内容保留在回收站。
6. “撤回上一轮修改”按恢复指令追加新版本。后续已有其他保存时拒绝自动撤回，避免覆盖；可指定恢复具体资料。

## 实现边界

- 新增 `application/chat_agent.py`，调用受限业务操作，不给模型任意代码或文件执行权限。
- 新增 `ui/static/chat_workspace.js`，接通首页发送、状态轮询、停止、删除确认和简单 API 表单。高级采样与按用途配置不再出现在普通流程中。
- 所有小说写入复用业务层及 revision/快照事务。会话复用原有 console 集合持久化。
- API 使用系统加密保存的连接；默认自动为 GPT 类模型选择 Responses，为其他兼容模型选择 Chat Completions，也支持现有 Gemini、Messages 原生连接。兼容选项可手动指定请求方式。不会自动改换供应商或失败重试。
- 桌面模式启动允许模型能力，但只有发送需求才调用模型；保存设置、打开软件不会自动生成。仍保留手动模式接口。
- 创作任务不设固定规划轮数、章节数或模型调用次数上限。模型每次最多返回20项操作作为一批，系统会自动执行后继续规划，直至模型明确报告完成；连续3批为空操作或重复相同工具参数时停止并说明无进展。API 错误、取消和 revision 冲突仍会停止任务，不自动重试。上下文有大小限制，超限会停止并报告，不静默丢弃附件或正式资料。
- 正文保存成功但资料分析失败时，正文保留，任务报告未完成，不能视为整轮成功。
- `library/chat-automation.json` 保存连接选择、运行记录和恢复指令，不保存密钥；恢复指令可能含修改前的正文。现有完整库备份没有新增这个伴随文件：迁移本轮自动化记录时须与 SQLite 一并保留。正式小说、原有正文历史与会话仍在 SQLite 中。
- 模型会根据上下文选择操作，真实供应商兼容性、创作质量、多轮行为和恢复交互尚待作者试用。

## 0.4.17 聊天交互修订

- 聊天框 Enter 直接发送，Shift+Enter 换行；中文输入法合成期间（包括 isComposing / keyCode 229）Enter 不触发发送，Ctrl、Alt、Meta 组合也不触发普通 Enter 发送。任务忙碌或附件处理中，普通 Enter 不重复发送，也不插入意外换行。键盘处理在常驻输入框上只绑定一次，通过现有表单 requestSubmit() 复用提交流程。
- 聊天重绘绕过文档草稿的滚动归零逻辑。使用实际滚动容器 #content 的已渲染项目/视图标记，在异步读取结束、替换 DOM 前即时捕获阅读位置，避免覆盖等待期间的上翻操作；重绘后通过 requestAnimationFrame 并校验渲染编号恢复。原在底部时跟随新内容，上翻阅读时保留位置，不抢焦点，不混用其他项目或视图的位置。
- 本轮最后的键盘、滚动及自动批次修订已通过语法检查与桌面目录构建，交互行为由用户试用；未运行测试套件。不调用真实创作模型、不访问用户小说资料，不在本轮扩展请求协议或 HTTP 524 处理。

## 0.4.17 本次产物与附件使用

本版已完成 Windows 桌面目录构建。作者从解包目录运行 `DualQuill.exe`；启动时须清除当前启动进程的 `ELECTRON_RUN_AS_NODE`。应用默认使用当前 Windows 用户的 DualQuill 数据目录，不依赖开发者的盘符。

- 可在聊天输入框独立整行粘贴本地文件或文件夹的绝对路径，发送时先通过本地路径 API 导入，再进行分类；路径应单独占据整条消息，不与用途说明混写。也可将绝对路径填入“导入本地路径”输入框，点击同名按钮，查看附件解析状态后填写用途并发送。未填写用途时自动分类。
- 上传按钮和拖放支持多个文件逐个处理，单文件最多 8 MiB；显式本地路径每次最多 30 个文件、合计最多 64 MiB，源文件只读，不修改原目录。
- 每次发送所选附件的提取文本合计最多 120000 字符（12 万字符）；超限应拆分任务，不静默截断。上传、路径读取和解析仅在本机执行，点击聊天发送后才将所选内容交给当前配置模型。
- 原件持久保存在当前用户库的 `library/attachments/<稳定UUID>/` 目录。迁移或备份时须将 `attachments` 目录与 SQLite 数据库一起保留；现有文档全量备份不包含原件。聊天任务及来源关联记录也应随库中的 `chat-automation.json` 一并保留。
- 最终源码已通过 214 个 Python 文件 AST 检查、app.js/chat_workspace.js JavaScript 语法检查及 diff 空白检查。桌面目录构建退出 0，包含 263 项后端与静态资源，source_digest 为 `029611a96f36ea099d112e3fcdcb51fbcb14d13df6d730893205b9bbaf4984e6`。没有运行测试套件或安装升级验收；后续真实创作由用户授权使用，不作为完整功能验收结论。
