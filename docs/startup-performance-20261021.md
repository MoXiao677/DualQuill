## 最小源码修复

- `domain/memory.py`：章节来源直接读取显式 current_version_id；构建整书来源目录时只为该次状态建立线性实体/版本索引，不跨 revision 或数据库缓存来源。
- `storage/json_codec.py`：资源节点数仅在保守上界已证明低于原配额时走快路径，深度仍在 JSON 解码前检查；出现转义引号或上界不能证明时回退原精确扫描。字符串/容器/标量节点配额、64 层深度、64 MiB 单记录限额不变。UTF-8 输入先验证，只有 Unicode escape 可能引入新 surrogate；有限浮点数在 decoder hook 校验，1e999 仍拒绝。
- `domain/models.py` 与 `storage/sqlite_repository.py`：只对与当前 validator 私有已验证记录的**完整值和容器/标量类型均相同**的不可变版本复用验证；True/1、1/1.0 不可互代。新记录、当前实体、ID/目标归属与全链 append-only 检查继续执行。内部复用私有已验证版本对象，外部返回和提交缓存仍保留原深复制边界。
- 每次读取仍对磁盘上每条整书快照的原字节计算 SHA；没有用文件大小、mtime、删除历史或后台跳过历史换取速度。

## 源码回归及限制

同一 history 夹具、同一主机的独立源码冷读对照为基线 13.322248 秒，最终源码三次为 4.666733 / 4.737613 / 4.631700 秒。每次为独立 Python 进程和任务自有库副本，库 SHA 不变。**这些只是 repository.get 冷读，不包含 EXE/首次 profile 备份、DOM、导航或输入，绝不替代 <5 秒启动验收。**

105 项定向回归通过：新增热点/拒绝用例 8、历史缓存 5、作者锁及身份/恢复 19、备份严格校验 28、旧文档模型 33、存储 12；0 fail / 0 error / 0 skip，12.355633 秒。另与精确共享 baseline 做 2014 个 JSON 接受/拒绝及原文等价对照、4 个来源目录状态对照，全部通过。两个有效算法 RED、所有试测观测器问题以及反而变慢的分块扫描实验均留存；变慢实验未进入最终补丁。

使用实际 EXE 的 background-test 隐藏/offscreen 桌面模式；未清系统文件缓存，spawn 前 SHA 读取会温热 OS 页面缓存，不声称物理冷盘启动。两份正式夹具都是 author-scope unlocked；锁、旧库、恢复复制和权限隔离另由定向用例覆盖。工作集为约50ms间隔加枚举开销的进程树采样下界，祖先退出可能漏计后代；真实 IME、可见窗口首次绘制、其他设备不在本测量范围。

最终统一新 EXE 由唯一主整合者构建并重新绑定、定向独验；本补丁没有得到新候选实际 <5 秒启动结论，包含首次备份的时间预算仍待实测。真实模型质量/费用、干净 VM、签名和发布许可继续按既有外部门槛处理，真实付费 0。
