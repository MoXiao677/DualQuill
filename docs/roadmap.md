## 第一阶段：建立基础

已完成模块目录、数据结构、JSON 示例与读取校验、基础测试和中文文档。

验收结果：示例与基础测试通过，原 README 的长期目标保留，不包含 AI API 调用和私人正文。

## 第二阶段：离线最小流程

v0.2 已完成以下离线流程：

1. 创建一本小说项目。
2. 手动填写全书大纲和人物。
3. 新建章节，填写细纲和正文。
4. 保存内容，并保留完整版本快照。
5. 关闭后重新打开，核对内容没有丢失。
6. 查看旧版本，选择恢复时创建一个新版本。

实际采用 SQLite 事务，将当前内容和完整工作区快照一起提交；失败回滚。revision 冲突阻止旧窗口覆盖。正式章节修改与恢复需要明确确认，既有历史不被覆盖。

已增加本地浏览器界面和双击启动入口；仍不依赖前后端框架。新增世界观、文风、每章 IDEA、本地 Skills 导入和作者/AI 使用指南，均可保存到磁盘。

此阶段继续离线运行，不接入模型 API。已用真实浏览器验证重开后内容一致、版本可查看恢复、Skills 资料原文显示，并通过数据与事务相关测试。

## 第三阶段：补充资料管理

先请作者用练习小说验证一章的完整流程，再优先增加 JSON 备份导入、章节重排和需要的搜索。已有世界观、文风和 JSON 导出；Skills 已能导入资料，尚未参与 AI 调度。正式长篇投入前，评估全文快照的存储增长并设计兼容迁移。

## 第四阶段：逐步加入 AI

作者确认后才接入模型。先增加一个可替换的模型适配器，明确费用、超时、错误处理和人工确认流程，再逐步增加审核、改写及多模型协作。

## 第五阶段：长篇一致性与完善

逐步建设剧情时间线、人物与世界观一致性检查，以及全书质量检查。每一步都应有可观察的结果，自动建议由作者选择是否采纳。
